### Key Design Decisions & Fixes
 
1. **Transition from Warp Specialization to Cooperative Double-Buffering:** Replaced the previous 1 loader warp + 4 math warps layout with a 128-thread (4 warps) cooperative layout. Because fine-grained NamedBarriers/mbarriers cannot be used inside the loop on Blackwell `sm_120` due to compiler JIT FFI bugs, warp specialization requires block-wide `sync_threads()`. Investigating `cutlass.pipeline.NamedBarrier` and `cutlass.pipeline.PipelineCpAsync` revealed that they trigger either `invalid instruction mnemonic 'bar.sync'` (due to host compilation passes attempting to compile PTX inline assembly as host x86_64 assembly) or `LLVM ERROR: Error: unsupported operation` (due to `nvvm.barrier` mapping bugs in MLIR lowering). This runs the loader and math warps in strict lock-step, leaving warps idle and reducing hardware utilization (taking 28.51 ms). The 128-thread cooperative model resolves this lock-step bottleneck and utilizes all threads for both loading and math.
2. **Flat Shared Memory Layout and recast_ptr:** Resolved a TVM/CuTe JIT compiler union bug that padded shared memory blocks to power-of-2 boundaries (128 KB instead of 96 KB), exceeding sm_120a's 99 KB SMEM limit and causing block launch failures for $BLOCK\_M=128$.
3. **Dynamic & Coalesced Copy Thread Layouts:** Calculated copy thread layouts dynamically to align with `BLOCK_K_STAGE` and prevent out-of-bounds partitioning on small block shapes (e.g. `BLOCK_M = 16`, `BLOCK_K = 8`). For X, the layout shape is `(copy_x_thr_m, copy_x_thr_k)` where `copy_x_val_k = min(8, BLOCK_K_STAGE)`, `copy_x_thr_k = BLOCK_K_STAGE // copy_x_val_k`, and `copy_x_thr_m = min(128 // copy_x_thr_k, BLOCK_M)`. For W, the layout shape is `(copy_w_thr_n, copy_w_thr_k)` where `copy_w_val_k = min(8, BLOCK_K_STAGE)`, `copy_w_thr_k = BLOCK_K_STAGE // copy_w_val_k`, and `copy_w_thr_n = min(128 // copy_w_thr_k, BLOCK_N)`.
4. **2D Grid Swizzling with Padded Grid Launch:** Decoded block indexes using a 2D grid swizzling pattern (tile size `SWIZZLE_X = 8`) to run head groups (`cta_h_group`) and sequence blocks (`cta_m`) concurrently inside swizzled block groups. This maximizes both $X$ and $W$ L2 cache hits. Grid dimensions are padded at host launch and clamped via `cutlass.min` to prevent out-of-bounds execution.
5. **Pre-partitioning and Vectorized LDS:** Moved shared memory partitioning and register fragment allocations outside the main loop to avoid layout math. Replaced scalar register loading loops with `cute.autovec_copy` to compile into vectorized LDS instructions.
6. **Dynamic Pipelining (ab_stage = 2 or 3):** Configured pipeline stages to dynamically select 3-stage triple-buffering if the total memory footprint fits safely under the 99 KB SMEM limit (requiring ~85.7 KB), and fall back to 2-stage double-buffering otherwise.
7. **WGMMA Hardware Incompatibility:** GeForce Blackwell (`sm_120`, RTX 5090) lacks the physical `tcgen05` (5th generation Tensor Core) and Tensor Memory (TMEM) hardware subsystems present in datacenter Blackwell GPUs (`sm_100`). Thus, `wgmma` instructions are physically unsupported on `sm_120` and trigger compilation failures. The kernel must target warp-level MMA (`MmaF16BF16Op`) instead.
8. **Blackwell SMEM Limit occupancy:** Blackwell `sm_120` has a 99 KB hardware limit per threadblock. Setting `BLOCK_N = 384` (grouping 2 heads) and `BLOCK_M = 64` allows high occupancy and maximizes L2 cache hits.
9. **Race-Free Epilogue Shared Memory Reuse:** Resolved a critical race condition where threads writing output elements to `sOut_bf16` would prematurely overwrite input values in `smem_accum` before other threads finished reading them. Introduced an explicit thread-barrier synchronization (`cute.arch.sync_threads()`) immediately after loading inputs into local registers and before starting epilogue math/writes.
10. **Autotuner Integration:** Implemented an autotuning script (`autotune.py`) that profiles candidate shape configurations (`HEAD_GROUP = 2, 4, 8`) by sacrificing sequence block size (`BLOCK_M`), selecting the configuration with the lowest latency and caching it to `autotune_cache.json`.
11. **Explicit 128-bit Store Vectorization:** Added `num_bits_per_copy=128` to `store_atom = cute.make_copy_atom(store_op, BFloat16, num_bits_per_copy=128)` and aligned memory offsets via `.align(16)`, enabling 128-bit vector stores to global memory.
12. **Register-Level Double-Buffering & Compile-Time Range_Constexpr Unrolling:** Implemented stage-level register double-buffering using two sets of register fragments (`rA_0`/`rA_1` and `rB_0`/`rB_1`) to overlap shared-to-register copy latency (LDS) with Tensor Core math. To prevent register spills to local memory caused by dynamic register indexing inside GPU loops, we unrolled the main loop at compile time using `cutlass.range_constexpr(self.k_tile_cnt)`, allowing all index calculations to resolve statically.
13. **Vectorized Epilogue Prefetching:** Replaced 64 scalar global memory loads per thread in the epilogue (which loaded `cos`, `sin`, and `rmsnorm_weight` element-by-element on-the-fly) with vectorized 128-bit global loads (`LDG.128`) into register fragments using `cute.autovec_copy`. This loads entire rows at once, using non-overlapping register lifetimes to keep register usage under the 255 hardware limit and reducing latency by 13% (saving 1.12 ms).
14. **Ahead-of-Time (AOT) Preloading and Stride Padding:** Preloaded RMSNorm weights and scales at launch, eliminating duplicate instructions and reducing register pressure. Stride-padded the epilogue shared memory buffer `sOut_bf16` by 8 elements (`BLOCK_N_padded = 392`) to map conflict-free to shared memory banks, reducing LDS bank conflicts from 32-way to 4-way and bringing overall execution latency down to **7.51 ms**.
